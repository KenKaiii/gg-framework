Add an optional `rewriteCommand` hook to `createBashTool`/`createTools`, so a caller can route the bash tool's plain foreground commands (`git status`, `ps aux`, `find`, ...) through an external compaction tool before they run — e.g. [rtk](https://github.com/rtk-ai/rtk), which rewrites common CLI invocations into token-cheaper equivalents. Nothing ships wired in; omitted by default, so behavior for every existing caller is unchanged. Scoped to the synchronous spawn path only (not `persist` or `run_in_background`), and every safety guard (plan mode, catastrophic-command, network policy) still runs against the original command before the hook is ever called — a rewriter cannot be used to bypass them. A throwing/rejecting or `undefined`-returning rewriter always falls back to the original command. The hook may return a Promise: the realistic implementation routes through an external process, and a synchronous version of that (`spawnSync`) blocks the whole event loop for any host running multiple sessions in one process — awaiting the hook by design closes that off instead of relying on every implementer to know not to use the sync form.

Also wires a real, opt-in consumer: `GG_RTK_REWRITE=1` enables an [rtk](https://github.com/rtk-ai/rtk)-backed rewriter at the ggcoder CLI entry point, proving the hook shape against an actual external-process integration rather than shipping an unused extension point. Off by default; whether/how this becomes discoverable (CLI flag, persisted setting) is a separate product decision this does not make.

Fix radio players surviving a hard kill, let OpenRouter point at a custom base URL, and sync gateway model catalogs.

**Radio: orphans kept streaming.** Players were tracked only in module singletons, so a daemon killed with `taskkill /F` (or a crash) left its `ffplay`/`mpv` running with nothing to stop it. The next daemon had `currentChild === null`, spawned another stream on top, and every restart added one more. On Windows it was worse: `spawn("ffplay")` resolves to a launcher shim (chocolatey's `bin\ffplay.exe`), so `child.kill()` killed the shim while the real `ffplay` — a grandchild — kept streaming. Players are now recorded by PID in the temp dir, reaped on daemon boot and again before each play, and strays are also found by scanning command lines for the app's own station URLs (a user's unrelated player is never touched). Termination is a forced tree-kill on Windows, which `child.kill()` alone does not guarantee.

**OpenRouter: editable base URL.** `AuthProviderMeta.allowCustomBaseUrl` makes the API-key form offer a base-URL override, stored on the credential in `~/.gg/auth.json` and picked up by `AgentSession` (`creds.baseUrl`). It can be changed later without re-pasting the key (`app_auth_baseurl`), the form prefills the URL in effect (`currentBaseUrl`), and the value is validated in Rust (`http(s)` only, trailing slashes stripped). Both `allowCustomBaseUrl` and `currentBaseUrl` are emitted by `app_auth_status` — the app reads provider metadata from Rust, not from the sidecar, so a flag added only to gg-core's metadata never reaches the modal.

**Gateway model sync.** A provider pointed at a custom endpoint no longer shows someone else's catalog: `POST /models/sync` reads that endpoint's own `/v1/models` (OpenRouter and OpenRouter-compatible gateways return `context_length`, `max_output_length`, `pricing`, `reasoning_parameters`, `supported_features`, `input_modalities`) and registers `ModelInfo` rows at runtime, so the context window, output cap, top reasoning level, image support and cost tier match the thing actually answering requests. Models that can't call tools are dropped and counted; ids are namespaced (`openrouter/<rawId>`) so they can't shadow another provider's static id, and gg-ai strips the namespace at the transport boundary. The catalog is cached in `~/.gg/gateway-models.json` and reloaded on boot. The same path syncs the real OpenRouter catalog when no custom base URL is set.

**Effort levels are the endpoint's, on the picker and on the wire.** `ModelInfo.thinkingLevels` carries the ladder a gateway declared (`reasoning_parameters.efforts`) instead of collapsing it to one rung, so a gateway offering low/high/xhigh/max no longer shows a single choice. `effortForRequest()` sends the chosen rung verbatim when the endpoint declared it — previously every non-OpenAI model was clamped, and `max` silently became `xhigh`, so a "configured but never delivered" level was indistinguishable from a working one. Ladders stay clamped for the statically-registered providers that need it (Fugu, Kimi K3, local endpoints). Also loads the synced catalog in the CLI, including its `--json` path, which previously returned before the model registry was populated.

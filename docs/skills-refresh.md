# Bundled skills: refresh checklist

The bundled skills live in `packages/ggcoder/assets/skills/<name>/`. The desktop
app's copy under `gg-app/src-tauri/sidecar/skills/` is generated by
`bundle:sidecar`; never edit it. Run this pass roughly monthly, and whenever a
skill's routing or a big upstream change (a spec, a law, a framework major) lands.

Last full pass: **22 October 2026**.

## 1. Is each skill still earning its place?

| Check                                               | How                                                                                                                                                                                                                                |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does it change behaviour?                           | Run the skill-value A/B in the private bench (`sv-*` tasks, `--variants on,off`: the same build with and without its skills) and the routing probes (`skill-not-for-rename`). A skill that changes nothing is a removal candidate. |
| Does it overlap another skill or the system prompt? | Each rule should live in one place. Always-on safety rules belong in the system prompt or a tool description, not in a skill that only loads for one kind of work.                                                                 |
| Is the description routable?                        | ≤ 240 bytes, "Use when/for …" + the words users actually say, plus a "Do NOT use" clause (enforced by `skills-routing.test.ts`).                                                                                                   |

## 2. Shape (Anthropic skill-authoring guidance)

Source: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices

| Rule                                                                                                                      | Why                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `SKILL.md` holds routing, the inline/always path and the hard rules; full-review depth goes in `references/`.             | The whole `SKILL.md` loads even for a one-line inline gate.                                                                   |
| References are one level deep, each linked from `SKILL.md` as a backticked `references/x.md` path.                        | The model may only skim files that are linked from other references; the test checks the paths exist.                         |
| Reference files over 100 lines start with a `## Contents` list.                                                           | A partial read still shows the file's scope.                                                                                  |
| No time-sensitive facts in `SKILL.md`; dated facts live in references with `[V]` / `[S]` / `[U]` markers.                 | Dates rot; markers tell the agent what to re-verify.                                                                          |
| Scaling sections say _when_ to fan out and _how to slice_, and name helpers by role.                                      | The shared mechanics are appended by the loader (`DELEGATION_RULES` in `src/tools/skill.ts`), and agent names differ by mode. |
| Assume the model is smart: cut explanation that doesn't change behaviour; keep every rule an evaluation proved necessary. | Every loaded token competes with the task.                                                                                    |

## 3. Fact refresh (dated content)

| Skill            | Highest-decay content                                                                                                 | Primary sources                                                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| compliance-guard | EU (AI Act, Digital Omnibus, CRA, DSA, EAA), UK (OSA/Ofcom), US state privacy/AI/minors laws, CIPA/TCPA, ADA Title II | EUR-Lex, Official Journal, regulators, legislature sites, Federal Register, court dockets    |
| bulletproof      | MCP spec revision, OAuth 2.1 draft, npm/PyPI registry policy, framework advisories, CWE Top 25 / OWASP lists          | modelcontextprotocol.io, IETF datatracker, GitHub changelog, GHSA/NVD, vendor security blogs |
| durable          | Postgres / Prisma / Drizzle versions, provider backup and PITR defaults                                               | release notes, provider docs                                                                 |
| lean             | Node release schedule, Core Web Vitals, framework majors                                                              | nodejs.org, web.dev                                                                          |
| others           | Source links only                                                                                                     | —                                                                                            |

For every changed fact: verify against a primary source, set the marker, and add a dated
entry to that skill's `references/provenance.md` (or its Sources line) listing what was and
was not re-checked. Never upgrade a marker without a source.

## 4. Verify

```bash
cd packages/ggcoder
pnpm vitest run src/core/skills-routing.test.ts
```

If a tool or prompt description changed, regenerate the golden on purpose:
`UPDATE_GOLDEN=1 pnpm --filter @kenkaiiii/ggcoder test -- system-prompt.golden`.

# Bundled skills: refresh checklist

The bundled skills live in `packages/ggcoder/assets/skills/<name>/`. The desktop
app's copy under `gg-app/src-tauri/sidecar/skills/` is generated by
`bundle:sidecar`; never edit it. Run this pass roughly monthly, and whenever a
skill's routing or a big upstream change (a spec, a law, a framework major) lands.

Last fact refresh (section 3): **22 November 2026** (bulletproof re-checked 27 November 2026). Last skill-value bench (section 1): **27 October 2026**. Trigger probes (section 1): **32/32 on Haiku 5.5, 22 November 2026** (1 rep; second model family not yet run).

## 1. Is each skill still earning its place?

The private bench is `bench/prompt-diet/` (gitignored). Run every bench on at least two model families (`--provider anthropic --model claude-haiku-5-5` and `--provider openai`): one model's routing habits are not the product's. Claude runs use GG's own Claude sign-in (sign in with Claude in GG once); ChatGPT runs need a sign-in with more than 2 hours left. Each run needs a sidecar bundle at `/tmp/gg-dirac-h2h/<variant>-sidecar/` (`pnpm build && pnpm --filter gg-app bundle:sidecar`, then copy `gg-app/src-tauri/sidecar`).

| Check | How |
| --- | --- |
| Does it change the result? | Skill-value A/B: `sv-*` tasks with `--variants on,off` (the same build with and without its skills). Graders check only the result. A skill with no outcome gain is a removal candidate; no gain **and** slower or costlier (wall time, tokens) means remove it. |
| Does it load when it should, and only then? | Trigger probes: `--tasks 'tr-*'` (one skill: `'tr-durable-*'`). Each visible skill has 5 should-load prompts and 5 near-miss should-not prompts; hidden skills have a must-never-self-load probe. Re-run after any description edit. A missed should-load or a fired should-not is a description fix, not a reason to add more rules. Grow each set toward ~10 + ~10 from real misses. |
| Does it overlap another skill or the system prompt? | Each rule should live in one place. Always-on safety rules belong in the system prompt or a tool description, not in a skill that only loads for one kind of work. |
| Is the description routable? | ≤ 240 bytes, "Use when/for …" + the words users actually say, plus a "Do NOT use" clause (enforced by `skills-routing.test.ts`). The imperative voice follows agentskills.io on purpose (Anthropic's guide prefers third person); the catalog strips the "Use when/for" prefix. |

## 2. Shape (Agent Skills spec and Anthropic skill-authoring guidance)

Sources: https://agentskills.io/specification and https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices

| Rule | Why |
| --- | --- |
| Frontmatter: `name` (lowercase-hyphen, ≤ 64, equals the folder name), `description`, optional `license`, `compatibility` (≤ 500 chars), `metadata.version` (`YYYY.MM.DD` of the last fact pass). Enforced by the "Agent Skills spec support" tests in `skills-routing.test.ts`. | Other agents read the same folders; a skill that breaks the spec breaks there first. |
| `hidden: true` (GG) or `disable-model-invocation: true` (spec) keeps a skill out of the catalog; it still loads by exact name. | Checklist-only skills, and manual-only skills imported from other agents, must not self-load. |
| `SKILL.md` holds routing, the inline/always path and the hard rules, under 500 lines; full-review depth goes in `references/`. | The whole `SKILL.md` loads even for a one-line inline gate. |
| References are one level deep, each linked from `SKILL.md` as a backticked `references/x.md` path. | The model may only skim files that are linked from other references; the test checks the paths exist. |
| Reference files over 100 lines have `## Contents` as their first section (test-enforced). | A partial read still shows the file's scope. |
| No time-sensitive facts in `SKILL.md`; dated facts live in references with `[V]` / `[S]` / `[U]` markers. | Dates rot; markers tell the agent what to re-verify. |
| Scaling sections say _when_ to fan out and _how to slice_, and name helpers by role. | The shared mechanics are appended by the loader (`DELEGATION_RULES` in `src/tools/skill.ts`), and agent names differ by mode. |
| Assume the model is smart: cut explanation that doesn't change behaviour; keep every rule an evaluation proved necessary. | Every loaded token competes with the task. |

## 3. Fact refresh (dated content)

| Skill | Highest-decay content | Primary sources |
| --- | --- | --- |
| compliance-guard | EU (AI Act, Digital Omnibus, Digital Fairness Act, CRA, DSA, EAA), UK (OSA/Ofcom, Information Commission), US state privacy/AI/minors laws, CIPA/TCPA, ADA Title II | EUR-Lex, Official Journal, regulators, legislature sites, Federal Register, court dockets |
| bulletproof | MCP spec revision, OAuth 2.1 draft, OWASP LLM/Agentic Top 10 editions, npm/PyPI registry policy, GitHub Actions defaults, framework advisories, CWE Top 25 | modelcontextprotocol.io, IETF datatracker, GitHub changelog, GHSA/NVD, OWASP, vendor security blogs |
| durable | Postgres / Prisma / Drizzle versions and EOL, PgBouncer, provider backup and PITR defaults | release notes, provider docs |
| lean | Node release schedule, Core Web Vitals and soft navigations, framework majors | nodejs.org, web.dev, developer.chrome.com |
| gg-guide | On-screen labels and features from `gg-app/src/changelog.ts` since the last pass | app source (`gg-guide-skill.test.ts` checks labels) |

For every changed fact: verify against a primary source, set the marker, and add a dated
entry to that skill's `references/provenance.md` (or its Sources line) listing what was and
was not re-checked. Never upgrade a marker without a source. Then bump `metadata.version`
in that skill's `SKILL.md`. A user copy in `~/.gg/skills`, `~/.agents/skills` or a project's
skills folder replaces the built-in and keeps its old facts; the sidecar log records each
replacement with both versions.

## 4. Adding a skill

Write the evaluation before the skill. Add result-only `sv-*` tasks and `tr-*` trigger
probes for it, run `--variants on,off` on two model families, and ship it only if the
result improves without a large slowdown. Published results point the same way as the
27 Oct bench: skills pay off for specialist or post-training knowledge, coding-process
skills gain least, and an unloaded skill gains nothing. When the knowledge is a few
lines, test an always-on prompt line against the skill as well.
